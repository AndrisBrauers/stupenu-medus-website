Create a **visually exceptional, highly art-directed, interactive website for a small Latvian honey farm**.

This is NOT a normal small-business website project.

The point of this project is to demonstrate what becomes possible when **AI makes custom creative coding cheap enough to use even for something as simple as a local honey farm website**.

A human agency would normally never spend the development time required to create elaborate bespoke interactions, custom animation systems, procedural graphics, unusual transitions, interactive storytelling and experimental layouts for a small honey producer.

We can.

Use that freedom.

I do not want "a really nice honey website."

I want something where another web developer opens it and thinks:

**"Why did somebody put this much craft into a honey farm website?"**

And then:

**"This is actually really good."**

---

# THE CORE PRINCIPLE

Do not approach this as:

> "What sections should a honey business landing page have?"

Approach it as:

> "What could a digital experience about bees, honey, seasons and a Latvian landscape feel like?"

The website still needs to ultimately sell honey.

But the commercial interface should emerge naturally from the experience instead of the whole website looking like an ecommerce template.

Think of this as a collaboration between:

- an excellent European graphic designer
- an experimental creative developer
- an editorial art director
- a motion designer
- and a beekeeper

It should feel **bespoke**.

Not generated.

---

# IMPORTANT: DO NOT MAKE A NORMAL LANDING PAGE

Avoid the standard sequence:

Hero
→ cards
→ features
→ story
→ testimonials
→ CTA
→ footer.

Do not simply make those sections prettier.

Break the structure.

Create rhythm.

Sometimes the screen can contain almost nothing.

Sometimes typography can dominate.

Sometimes photography can dominate.

Sometimes an interactive detail can occupy an entire viewport.

Let elements overlap.

Let layouts become asymmetric.

Let text occasionally follow unusual composition.

Allow sections to visually bleed into one another.

Use different spatial compositions throughout the page instead of repeating the same container width over and over.

The page should feel like **one continuous designed experience**, not twelve React components stacked vertically.

# OPENING EXPERIENCE

Do NOT begin with:

large headline
paragraph
two buttons
photo on right.

Instead, create an opening that immediately establishes that this website is unusual.

For example:

The visitor initially sees an almost full-screen Latvian meadow.

Very little UI.

Small typography somewhere in the composition:

**[SAIMNIECĪBAS NOSAUKUMS]**

**Medus no [NOVADS].**

The scene should have subtle life.

Wildflowers can move slightly.

Tiny insects or pollen particles may drift.

Nothing cartoonish.

Nothing like a videogame.

Think atmospheric, photographic, almost cinematic.

As the user begins scrolling, the landscape itself should begin becoming part of the interface.

Typography emerges.

Elements move at different speeds.

A bee could subtly travel through parts of the composition.

Not as a cute mascot.

As a visual thread connecting the experience.

Eventually the first major statement appears:

**Šeit sākas mūsu medus.**

Not beside a photograph of honey.

In the landscape where the honey actually begins.

# MAKE SCROLLING PART OF THE DESIGN

Scrolling should not simply move the page downward.

Use it as a storytelling mechanism.

Create several carefully designed scroll-driven transitions.

Possibilities:

### Meadow → Hive

As the visitor scrolls away from the meadow, natural irregular shapes gradually become geometric.

Flower positions begin suggesting a hexagonal structure.

The screen slowly transitions into honeycomb geometry.

Do this subtly.

Not with an obvious "honeycomb animation."

---

### Hive / Honeycomb

Create an interactive honeycomb composition.

But avoid the cliché of filling the entire screen with yellow hexagons.

It might begin almost invisible.

Lines gradually form.

Individual cells may contain:

- tiny pieces of photography
- harvest dates
- flower names
- locations
- different honey colours
- small fragments of text

Hovering over cells could gently reveal information.

The structure should feel editorial and artistic, not like a dashboard.

---

### Honey transition

Experiment with a **custom liquid-like transition**.

For example, when transitioning from the apiary story into products, warm amber material could appear to flow, stretch or distort across part of the page.

This could be built using:

- Canvas
- SVG filters
- WebGL
- shaders
- masking
- displacement effects
- CSS where appropriate

Do NOT use a giant generic gradient blob.

It should evoke the viscosity and translucency of real honey.

Keep it elegant.

If true liquid simulation is excessive, fake it beautifully.

The illusion matters more than physical accuracy.

For example:

A jar appears almost like a product photograph inside a large empty composition.

As the visitor moves the pointer:

- highlights on the glass subtly shift
- the label moves almost imperceptibly with perspective
- the shadow responds slightly
- honey inside the jar has subtle depth

Scrolling or dragging could rotate between honey varieties.

For example:

**Griķu**

**Liepu**

**Krēmveida**

A mobile version should work with swipe instead of pointer movement.

Do not require real 3D if a convincing layered 2D implementation produces a better result.

# MOTION DESIGN

Motion needs proper direction.

Avoid the default:

opacity: 0
transform: translateY(20px)
→ animate in.

That animation can exist occasionally, but it cannot be the whole motion language.

Develop a coherent motion system.

Use combinations of:

- masks
- clipping
- image reveals
- typography movement
- layered parallax
- slow perspective shifts
- material distortion
- scroll-linked motion
- subtle inertial movement
- SVG path animation
- canvas effects

Movement should generally be:

slow
controlled
physical
organic.

No bouncy startup animations.

No excessive spring physics.

No "look how animated this is."

# PERFORMANCE MATTERS

This is creative development, not a tech demo that destroys the browser.

Target smooth interaction.

Lazy-load expensive assets.

Respect device capabilities.

Reduce effects on weaker devices.

Respect:

The website should remain usable without its most advanced effects.

# INTERACTION PHILOSOPHY

This website should still demonstrate what AI-assisted creative development makes possible.

But the sophistication should exist in **execution**, not the amount of stuff on screen.

I would rather have:

**3 exceptional interactions**

than:

**25 mediocre animations.**

Potential interaction vocabulary:

- geometric masks derived from the logo
- honey-drop transitions
- custom image reveals
- subtle responsive product lighting
- cursor proximity effects
- product transitions
- unusual but restrained typography transitions
- brand geometry that changes as the visitor scrolls
- high-quality page transitions
- sophisticated cart opening animation
- subtle liquid/surface-tension effects

Everything must feel connected to the existing Stupēnu Medus identity.

Whitespace/negative space is important.

Do not fill every empty region.

Do not assume that empty space needs:

icons

animations.
